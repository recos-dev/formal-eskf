# INS covariance code generation

Generate the complete INS covariance calculation, including rotated process
noise, with deterministic CSE, 120 upper-triangle entries and 105 mirrored
copies. The kernel consumes the existing core's `F`, `P`, `R` and diagonal `Q_i`.
Transition-matrix producers, observation Jacobians, correction and reset remain
the existing C++ implementations; they are not generated by this package.

The pinned header is
[ins_covariance.hpp](../include/formal_eskf/eskf/generated/ins_covariance.hpp).
**The production core still uses dense covariance prediction.** Native evaluation
uses an explicit [test-only patch](tests/integration.patch) in copied headers
under `output/`; it does not edit the production implementation.

## Generate and check

From the repository root, with Python 3, SymPy and `clang-format-14` installed:

```bash
python3 -m pip install -r codegen/requirements.txt
python3 codegen/generate.py --pin
python3 codegen/generate.py --check --pin
python3 -m unittest discover -s codegen/tests -v
```

Generation runs `clang-format` with the repository's `.clang-format`, then checks
the **formatted** source and all 225 exact identities before publication. Set
`CLANG_FORMAT` to select another executable; its version, binary hash and style
hash are recorded. Do not hand-edit generated C++ or generated Lean files.

The default scratch output is `output/codegen/ins/`, containing the header and
`manifest.json`. `--pin` also writes/checks the canonical include header. The fixed
date tag is `2026-11-18`; generation never uses today's date. The manifest records
core/specification/tool fingerprints, compiler-independent scalar operation
counts and assumptions. It identifies artifacts, not executed proof results.
`--check` does not rewrite the header or manifest.

## Formal checks

```bash
python3 codegen/generate.py --check --pin --lean formal/lean/FormalESKF/codegen
./scripts/verify_lean.sh --wfail
./scripts/verify_esbmc.sh codegen --list
./scripts/verify_esbmc.sh codegen
python3 codegen/check_controls.py
```

Apply the [proof resource limits](../docs/guides/verification.md#proof-execution-resources)
before running real verifiers. `--list` only inventories profiles. `--lean` writes
certificate sources; it does not execute Lean. The Lean runner builds generated
rows sequentially. `check_controls.py` requires real Lean and ESBMC rejection of
an incorrect sign and an out-of-bounds read, respectively; a timeout does not pass.

| Evidence | Scope |
|---|---|
| Generated Lean `Model`, `Row00`–`Row14`, `Entries` | Parsed scalar expressions equal the independent real matrix expression; complete matrix assembly |
| Handwritten Lean `Properties` | Symmetry and conditional real-arithmetic PSD preservation |
| Handwritten Lean `ErrorBounds` | Forward-error propagation conditional on local rounding inequalities |
| ESBMC `codegen` | Actual pinned header and production `Matrix`, fixed-array storage; bounds/access safety for binary32/64, without arithmetic range restrictions |
| Native rational checker | Recorded finite operations match IEEE RNE simulation and propagated error bounds; comparison with dense uses identical producer inputs |

Canonical Lean sources are in
[formal/lean/FormalESKF/codegen](../formal/lean/FormalESKF/codegen). Export preserves
the two handwritten files, and the tool tests compare generated certificates
with a fresh export. There is no machine-checked Lean-to-C++ or compiler refinement.
ESBMC's storage backend does not prove Eigen/PX4 internals or numerical accuracy.

## Native evaluation

The harness requires an x86 host with SSE so it can check FTZ/DAZ, and a GCC- or
Clang-compatible C++20 compiler. Eigen is the default backend; PX4 headers remain
external and are never downloaded or copied into the repository.

```bash
python3 codegen/evaluate.py native
python3 codegen/evaluate.py benchmark
python3 codegen/evaluate.py stack
```

`native` builds dense/generated pairs for float/double, both attitude modes and
`-O2`/`-O3`, then runs rational certification. It exercises prediction consistency,
all state/covariance alias combinations, failure atomicity, finite outputs and
symmetry. The fixed corpus includes ordinary inputs, invalid inputs, signed
zeros, subnormals, cancellation and wide exponents. `certify` rechecks existing
records without recompilation; missing records or stale source/dependency hashes
fail. The asymmetric-prior diagnostic is outside mathematical equivalence.

Select additional profiles explicitly:

```bash
python3 codegen/evaluate.py native --backends eigen px4 --px4 /path/to/PX4-Autopilot
python3 codegen/evaluate.py native --sanitize --optimizations O1 --output output/codegen/sanitizers
python3 codegen/evaluate.py native --cxx clang++-14 --optimizations O2 --modes 0 --output output/codegen/clang
python3 codegen/evaluate.py stack --optimizations O3 --arm-cxx /path/to/arm-none-eabi-g++
```

Use `--eigen` for nonstandard Eigen include locations and repeat `--cxx-flag` for
host toolchain flags. Sanitizer runs enable ASan/UBSan, not LeakSanitizer.
Benchmarking rejects instrumented builds, pins one host CPU and alternates paired
runs. It measures the kernel, full prediction and prediction plus accel/mag
corrections in default Exp mode. These are host timings, not target WCET.

Stack evaluation uses default Exp mode, GCC frame/call-graph output and Linux
alternate-stack observations. It reports unresolved external frames explicitly. Cortex-M7
cross-compilation is optional; unavailable target profiles remain unavailable.
Known frame paths and observed written bytes are **not** whole-program stack
bounds. Inspect `stack.json` before drawing target conclusions.

Reports, compiler commands, dependency hashes and raw records stay under the
chosen ignored output directory. Release evidence must be retained according to
the [evidence policy](../docs/guides/verification.md#record-ownership-and-reuse).

## Structure and remaining boundaries

- `generate.py`: formatting, generation, provenance and pinning.
- `evaluate.py`: isolated native, numerical, timing and stack evaluation.
- `check_controls.py`: real-verifier negative controls.
- `ins/covariance.py`: symbolic model, staged CSE and C++ emission.
- `ins/verify/`: independent source, algebra, Lean, IEEE and record checkers.
- `tests/native/`: shared INS fixtures, native checks and stack probes.
- `formal/cpp/esbmc/codegen.cpp`: actual generated-kernel memory proof harness.

Equivalence requires the core's structured transition, symmetric prior covariance
and diagonal impulse noise. Real PSD preservation additionally requires PSD prior
covariance and nonnegative noise. The formulation remains the core's truncated
right-local INS15 model, including its first-order bias coupling.

Before production selection, review [E-PCOV](../docs/spec/requirements/core/covariance-prediction.md)
for upper-triangle mirroring versus two-triangle averaging, asymmetric inputs and
overflow/status behavior. The isolated experiment deliberately records status
and numerical differences rather than claiming identical IEEE executions.

The error bound covers recorded finite binary32/64 operations with nearest
ties-to-even, gradual underflow, no FMA contraction and no fast-math. It is not a
uniform deployment-domain error budget, a floating-point PSD theorem, or an
end-to-end estimator stability guarantee. Negative principal-minor witnesses are
reported; absence of a witness does not prove PSD. Target backend/libm accuracy,
full target stack/WCET and production caller composition remain separate work.
AHRS code generation is not included in this INS package.
